## 3. DAILY COURSE STRUCTURE AND SCHEDULER

Ежедневный урок состоит из трёх связанных частей:

- 09:00 `Europe/Moscow` — **РАЗБИРАЕМ**: понятное объяснение одной темы для новичка с конкретным примером;
- 15:00 `Europe/Moscow` — **ПРОБУЕМ**: одно выполнимое практическое действие по утреннему объяснению;
- 20:00 `Europe/Moscow` — **ЗАКРЕПЛЯЕМ**: короткое задание, закрепление той же темы и конкретное приглашение написать результат/ответ в комментариях.

Все части образуют один законченный урок: объяснение → практика → закрепление. Вечерняя часть не должна вводить новую несвязанную тему.

Scheduler jobs:

- `publish_course_explain` — 09:00;
- `publish_course_try` — 15:00;
- `publish_course_reinforce` — 20:00;
- `prepare_course_days` — 00:10;
- `reconcile_course_publications` — каждые 10 минут;
- `prepare_course_on_startup` — one-shot startup preparation;
- `reconcile_course_on_startup` — one-shot startup reconciliation;
- `publish_marketcode_article` — отдельный MarketCode job, 12:00.

Для course cron jobs используются `max_instances=1`, `coalesce=True`; publication jobs также имеют `misfire_grace_time=300`. APScheduler job store остаётся process-local, а важное состояние и idempotency хранятся в PostgreSQL.

Reconciliation рассматривает только сегодняшний curriculum day, выбирает последнюю наступившую часть, допускает catch-up в пределах `COURSE_CATCHUP_MINUTES=90`, помечает более ранние просроченные части как `missed` и не публикует несколько частей пачкой. Startup recovery возвращает зависшие claims в retryable state, не затрагивая успешные публикации.

Provider: OpenRouter.

- fallback: `google/gemini-2.5-flash`.

Course generator не использует legacy free cascade. Fallback применяется не только при HTTP/API failure, но и после исчерпания quality attempts primary-модели.

Генерация выполняется на русском языке по prompt `prompts/course_lesson_prompt.txt`. Технический OpenRouter header ASCII-safe:

```text
X-OpenRouter-Title: HochuVseZnat-AI
```

Замена кириллицы в техническом HTTP-заголовке не переводит статьи на английский. Header идентифицирует приложение на уровне HTTP; язык и требования к контенту задаются русскоязычным prompt и curriculum. Все course materials остаются русскоязычными.

API request использует `max_tokens=2400`, `temperature=0.35`, timeout 180 seconds. Модель должна вернуть один JSON с тремя связанными частями. Ответ с `finish_reason=length`, пустой ответ, invalid JSON или не прошедший quality материал не считается готовым.

## 5. OFFICIAL SOURCES AND GENERATION

Каждый curriculum day содержит official source URLs. `SourceRetriever` получает их до генерации, извлекает читаемый текст и вычисляет content hash.

Если обязательный источник недоступен и нет ни одного успешно полученного required source, слепая генерация запрещена. После успешной генерации реально использованные source snapshots сохраняются в PostgreSQL вместе с lesson artifacts.

Course flow не использует web search, RSS, legacy random topic selection, Pexels или Pixabay. Тема определяется исключительно curriculum.

## 6. QUALITY VALIDATION

AI должен создавать естественно завершённые тексты. Production validator проверяет:

- наличие ровно трёх частей;
- допустимую длину каждой части;
- отсутствие пустого текста и Markdown fences;
- отсутствие model meta-instructions;
- лексическую связь практики с объяснением;
- связь закрепления с предыдущими частями;
- отсутствие чрезмерного повторения и одинаковых вступлений;
- наличие явного практического действия в «ПРОБУЕМ»;
- конкретный CTA и приглашение в комментарии в «ЗАКРЕПЛЯЕМ»;
- отсутствие дословного повторения CTA предыдущих уроков;
- отсутствие новой несвязанной темы в вечерней части.

Production length limits:

- РАЗБИРАЕМ: 850–1000 символов;
- ПРОБУЕМ: 650–900 символов;
- ЗАКРЕПЛЯЕМ: 450–750 символов.

Если AI-версия не проходит quality:

1. Формируется repair feedback с точной причиной отказа.
2. Модели передаётся отклонённый JSON, чтобы она редактировала конкретную версию, а не писала материал вслепую заново.
3. Feedback различает превышение maximum, недобор minimum и другие quality problems.
4. Корректные части предлагается сохранить максимально близко к текущей версии.
5. После исчерпания attempts primary используется configured fallback.
6. Каждая новая версия снова проходит полный validator.

### Safe length normalization — не заменять string slicing

Hard cut не используется. Код не режет текст по количеству символов и не оставляет оборванное предложение.

Если часть превышает maximum, normalization:

- работает только по границам целых предложений;
- удаляет целое предпоследнее предложение, только если результат не станет короче minimum;
- сохраняет начало текста;
- сохраняет финальное предложение и CTA;
- не генерирует и не дописывает текст самостоятельно;
- после каждого результата требует полную quality validation.

Если нормализованный материал всё ещё нарушает любой критерий, он не считается готовым и уходит в AI repair/fallback либо `needs_review`. Будущему разработчику нельзя заменять эту логику обычным `text[:limit]` или другим hard slicing.

Ошибка одной платформы не блокирует остальные: у каждой платформы отдельный claim, `try/except` и persistent result. Aggregate alert возможен только при полном отказе всех платформ для части.

На момент preparation `platform_publications=0`: будущие lessons только подготовлены, но не отправлены заранее. Ручные test publications в ходе запуска курса не выполнялись.

## 14. DZEN OPERATIONAL NOTE

Dzen Playwright/auth/storage-state flow во время course migration и bugfixes 13 августа не изменялся.

Dzen session периодически может истекать. При истёкшей авторизации publisher должен завершиться явной auth/session error до успешной публикации. Оператор вручную обновляет `DZEN_STORAGE_STATE_JSON` в отдельной operational задаче.

Автоматический login/re-login не добавлялся. Не изменять selectors, auth, cookies или Playwright flow без отдельной подтверждённой проблемы и отдельной задачи.

## 16. WHAT IS NOW AUTOMATIC

Полный production cycle:

1. Curriculum определяет lesson или special day на дату.
2. Preparation заранее получает official sources.
3. Course AI создаёт три связанные русскоязычные части.
4. Quality pipeline проверяет длины, структуру, связность, action, CTA и anti-repeat.
5. При необходимости AI получает repair context; после exhaustion primary используется configured fallback.
6. Небольшое превышение длины может быть нормализовано только по границам целых предложений с повторной полной validation.
7. Renderer создаёт три сезонных JPEG covers.
8. Lesson, parts, source snapshots, cover bytes и hashes сохраняются в PostgreSQL.
9. В 09:00, 15:00 и 20:00 scheduler берёт уже подготовленный artifact.
10. Каждая платформа публикуется и фиксируется независимо.
11. Reconciliation восстанавливает допустимый пропущенный запуск и не создаёт публикационный burst.
12. Ночное и startup preparation автоматически двигают окно вперёд.

После production launch не требуется вручную придумывать тему или создавать каждый новый урок. Оператор нужен только при явной ошибке источника/AI/platform auth, `needs_review`, истечении Dzen session или редакционном изменении curriculum.
